# INC-001 War Room — Fortify / Threat Model (INSTRUCTOR)

Scope: the exercise **scaffolding** (injector, incident API, logging, isolation,
instructor controls). The blogging application's authorization flaw is the
*intended* teaching defect and is documented in `INSTRUCTOR-RUNBOOK.md` /
`REMEDIATION.md`; it is deliberately present and out of scope for hardening here.

| Area | Risk | Control | Verified |
|---|---|---|---|
| **Authentication** | Scaffolding weakens the app's login | Untouched. Injector authenticates as its own synthetic users via the real `/api/auth/login`; no bypass, no backdoor account with a known-weak default that a learner could reuse elsewhere (passwords are long, random-ish, and local). | `npm test` (auth suite green) |
| **Authorization (instructor controls)** | Learner triggers/resets the incident or peeks at answers | `/api/incident/trigger` and `/reset` require `WAR_ROOM_INSTRUCTOR_TOKEN`, compared with `crypto.timingSafeEqual`. **Fail closed:** no token configured ⇒ controls disabled (403). | 403 without/with wrong token; 200 with token (validated) |
| **BOLA / IDOR** | The exercise itself | This is the taught defect; the injector demonstrates it with synthetic data only. The scaffolding adds no *new* BOLA (incident status is public read-only and object-free). | remediation suite red→green |
| **Privilege escalation** | Injector or incident routes grant elevated rights | The injector only exercises normal `user`-role sessions; no role is set to `admin`; incident routes never mint sessions or change roles. | source review; injector sets no role |
| **Information disclosure** | The alarm/brief reveals the root cause; the log leaks secrets | Public incident endpoints return symptoms only — no cause, endpoint, or account (asserted by test). `warroom_incident.evidence._instructor` is never served. Access log stores a **session fingerprint** (first 8 hex), not the session secret, and no passwords/hashes. | `warroom_authz.test.js` "symptoms only" + "no spoiler label"; log schema |
| **Incident injector** | Fabricated evidence; runs against the wrong target; double-fires | Makes **real** HTTP calls to its own `PORT` and records nothing by hand. Refuses to fire while an incident is already active. Reset is transactional and scoped to `@warroom.local` accounts. | injector summary reflects DB truth; double-fire skipped; reset removes only synthetic rows |
| **Instructor controls** | Token in logs / source | Token comes from the environment; a per-squad default is generated by `warroom.sh` and printed only to the instructor's terminal on `up`. Not committed. | grep: no token literal in tree |
| **Learner controls** | Learners can only investigate, not cheat the state | Learners need no token; they read status and the brief. Trigger/reset are refused to them. | 403 checks |
| **Squad isolation** | Squad 1 affects Squad 2 | Each squad is a distinct Compose **project** with project-scoped volume and per-squad ports (`8080+n`, `55950+n`). `down -v` targets one project. | validated: squad 2 idle while squad 1 active; separate volumes/ports; teardown scoped |
| **Reset** | Destroys learner-created content or another squad's data | Deletes only rows owned by `@warroom.local` users, within one squad's DB, in a transaction; clears its own access log and incident row. | post-reset: 0 synthetic users, learner content pattern preserved by ownership filter |
| **Replay / determinism** | Non-deterministic or non-repeatable incident | Fixed sequence; `reset`→`trigger` reproduces it; the fuse is clamped to `[5s, 24h]`; timer is `unref`'d so it never wedges shutdown. | re-run test; clamp in `config.js` |
| **Logging / evidence** | Logging breaks requests or floods | `res.on('finish')`, best-effort DB write wrapped in try/catch; incident-status polling is excluded so it does not bury the real activity. | logger source; request still 200 on log failure |
| **API abuse / DoS** | Injector or endpoints hammer the app | One bounded sequence per trigger; no loops; incident status is a single cheap read. Not exposed to the internet (local lab). | source review |
| **Config safety / fail closed** | Scaffolding leaks into the plain lab or production | Everything is gated on `WAR_ROOM_ENABLED`; when unset, no middleware, routes, tables, or timer are added and the app is byte-for-byte the original behaviour. No production, no real data, no external targets. | `index.js` guards; base `auth`/`health` suites unchanged |

**Base regression:** the original `auth.test.js` and `health.test.js` pass
unchanged with the scaffolding present (32 tests green including the new
always-green suite). The taught defect is confined to the three documented routes.
