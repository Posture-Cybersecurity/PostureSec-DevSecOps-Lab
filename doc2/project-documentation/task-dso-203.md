# Document the single points of failure

| **COMPONENT**           | **FAILURE & IMPACT**                                                                                                                                                       | **DETECTION**                                                  | **RECOVERY**                                                               | **MITIGATION**                                                              | **STATUS**   |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------ |
| **Node / PM2**          | Backend process restart causes brief API interruption; PM2 restores the application.                                                                                       | `pm2 status`, restart counter, PM2 logs.                       | PM2 restarted `posturesec-backend`; API returned `200 OK`.                 | PM2 cluster mode; migrate to ECS/EKS behind ALB for HA.                     | **OBSERVED** |
| **Nginx**               | Stopping Nginx caused complete frontend and API outage; port `80` became unreachable.                                                                                      | `curl` returned `Failed to connect`; `systemctl status nginx`. | `systemctl start nginx` immediately restored frontend and API.             | Multi-AZ ALB for highly available ingress and SSL termination.              | **OBSERVED** |
| **PostgreSQL**          | Stopping PostgreSQL removed the database listener; DB-dependent operations would fail, while `/api/health` remained `200` because the endpoint does not require DB access. | `ss -tulpn \| grep :5432` returned nothing.                    | Restarting PostgreSQL restored `127.0.0.1:5432`; API remained operational. | Move PostgreSQL to RDS Multi-AZ with automated backups/failover.            | **OBSERVED** |
| **Root EBS Volume**     | Limited `6.7 GB` root volume creates a disk-exhaustion risk; writes can fail when capacity is exhausted.                                                                   | `df -h /`; `fallocate` returned `No space left on device`.     | Remove/truncate unnecessary files and restore available capacity.          | Dedicated/expandable EBS storage, CloudWatch disk alarms, centralized logs. | **OBSERVED** |
| **EC2 Instance / Host** | Single-instance failure would remove Nginx, Node/PM2 and PostgreSQL simultaneously.                                                                                        | Instance/EC2 status checks, SSH/application connectivity.      | Instance replacement or snapshot restoration.                              | ASG across AZs; decouple PostgreSQL into RDS.                               | **OBSERVED** |
